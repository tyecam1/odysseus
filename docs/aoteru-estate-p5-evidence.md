# P5 — laptop Claude routing skill (lab-first slice)

Compact durable record. Do not reread unless a dependency changes.

Scope: the execution contract's "Laptop Claude routing skill — required
UX" binding rule, interpreted lab-first per
`docs/aoteru-lab-first-continuation.md` ("auto and lab work now; home must
fail truthfully as unavailable"). Not the full plan §7 (MCP servers, all
six lifecycle hooks, Codex integration) — that's the rest of P5, still
open.

## Built

- `core/database.LogicalSession` (`logical_sessions` table): `host_id`,
  `repo_id`, `worktree_path`, `claude_session_id`, `lease_id`, `engine`,
  `status`, `last_result` — the contract's minimal session-mapping fields.
  Distinct from `ParkLease` (P3): a session can exist without ever
  acquiring a mutation lease.
- `agent claude <auto|lab|home> "<task>" [--repo ID]` and
  `agent claude where`, extending the existing CLI (no second launcher):
  - Host resolution is purely by registered `role` in `config/estate.yaml`
    (`lab`→role `lab`, `home`→role `home`, `auto`→this host if registered,
    else first `lab`/`home` role) — no hardcoded hostnames anywhere in the
    dispatch code, matching the contract's explicit requirement.
  - Reachability is a real check, not an assumption: this host is
    reachable by construction; anything else needs `tailscale: true` +
    a live TCP probe of `tailscale_dns:22` within a bounded timeout.
  - Repo resolution reuses P1's `_resolve_repos`/cwd-matching — no path
    the caller has to supply.
- `~/.claude/skills/aoteru-estate-routing/SKILL.md`, generated by
  `agent sync` (not hand-authored once and left static) — content is
  exactly the four `agent claude` invocations plus explicit instructions
  not to hardcode anything and to report `"ok": false`/nonzero exits
  truthfully rather than retrying or fabricating a result.

## Correction (verifier-caught)

The independent fresh-context verifier ran its own end-to-end tests
against this evidence and found a real inconsistency: the `home`-
unreachable and missing-task failures exited nonzero (via `fail()`), but
the claude-binary-missing failure went through `emit()` — which always
returns/exits 0, regardless of the `"ok": false` in the JSON payload it
printed. The JSON itself was honest; a caller checking only the exit code
(shell `&&`, CI) rather than parsing `"ok"` would have seen success. Fixed
by calling `sys.exit(1)` after `emit()` in that branch; reverified live
(`agent claude lab ...` now exits 1, same JSON as before). All three
failure paths in `cmd_claude` now exit nonzero consistently.

## The real, honest boundary hit (not worked around)

No `claude` CLI binary exists on this host (`shutil.which("claude")` →
`None`) — checked before writing any dispatch code, not discovered after.
This means the actual "launch a native Claude session" step cannot be
implemented *or tested* from this environment at all, regardless of
lab-first scope. Rather than writing untested speculative subprocess-spawn
code for that step, the implementation stops at: resolve host → check
reachability → resolve repo → record the `LogicalSession` → check for the
`claude` binary → report the honest failure. The interface this leaves
(session already recorded, host/repo already resolved, one `subprocess.run`
call away from a real launch) is what a future session with the binary
present extends, not redesigns.

This was also a deliberate scope decision flagged to the operator before
starting: spawning nested Claude Code processes is a new category of
action beyond anything done earlier this session (file/config/network
changes), so the plan going in was to build the safe deterministic parts
and ask before wiring up real process-spawning — which turned out to be
moot once the binary was confirmed absent.

## Deferred

- **Actual native `claude` launch** — blocked on the binary not existing
  in this environment, not a lab-first policy choice. Revisit wherever a
  session has the binary.
- **`home` dispatch beyond the truthful-failure path** — needs the home PC
  on the tailnet first (P2's open item).
- **Remote (non-local) dispatch via SSH** — `cmd_claude` explicitly detects
  "target host isn't this host" and fails with a clear "not implemented
  from this session" message rather than attempting it; there is no second
  *reachable* worker to dispatch to yet even if the binary existed.
- **Codex / local-model engine modes, MCP-based invocation, lifecycle
  hooks (SessionStart/UserPromptSubmit/PostCompact/SessionEnd/PreToolUse/
  PostToolUse)** — full plan §7 scope, not part of this lab-first slice.
- **Lease integration in dispatch** — `LogicalSession.lease_id` exists in
  the schema but isn't populated yet; wiring dispatch to actually acquire
  a `ParkLease` is reasonable next work once real launch exists, not
  useful to build ahead of a launch step that can't run yet.

      untested and needs a session running there
