## Proposed bounds and HTTP contract

Default the server-side paid read-only liveness switch to off. Preserve the synchronous request path and its current values with the switch off, including the existing HTTP watchdog override and explicit CLI `--timeout`. The worker must accept the new mode only from an authenticated, qualified, correctly routed launch.

Use the durable execution ID and the existing `GET /api/estate/run/{execution_id}` observation path when the switch and the client's polling capability are both active. The lab service is behind a registered tailnet proxy. The full HTTP deadline chain could not be confirmed from this session, and the current watchdog cannot cancel the model call. A short submit returns once the execution row and replay claim are durable. Short polls use `wait=0`, so inference duration never determines the lifetime of an HTTP request. A caller that omits polling capability keeps the legacy synchronous behavior during the transition. Clients downgrade only on an explicit pre-admission response. For an ambiguous submission, recover the client-known ID, including when the server never sent an acknowledgement. A rollback prevents new liveness admission and keeps observation available for IDs already accepted.

One server function should validate finite positive settings and derive all enabled-mode values from the inactivity window `N` and absolute inference ceiling `C`. Send the derived bounds to the worker and advertise the default observation budget in the submission receipt. The CLI remains independently distributable and consumes the server value instead of maintaining a second timing table.

| Budget | Proposed default | Derivation and use |
| --- | ---: | --- |
| Inactivity `N` | 180 s | Retains the existing three-minute window for a silent run. Require `0 < N < C`. |
| Inference ceiling `C` | 900 s | Candidate from the original incident with a separate inactivity clock and owned cleanup. |
| Setup `S` | 120 s | Shared cap for route and worker setup, including repo resolution, version and catalogue discovery, and launch. Enforce elapsed time across probes and the remaining budget on each timed operation. |
| Cleanup `K` | 30 s | Reserved for stop, tree quiescence checks, pipe drain and terminal persistence. Uncertain cleanup stays observable under the same ID. |
| Worker envelope `W` | 1,060 s | `S + C + K + 10` for response and attestation. Pass the remaining envelope time across worker boundaries. |
| Worker transport `T` | 1,075 s | `W + 15` using the existing local and SSH transport margin once. |
| HTTP submit limit `H` | 210 s today | The current watchdog bounds submission, and a poll reads the durable state with zero long-poll wait. The ID must be known or recoverable even if submission acknowledgement is lost. |
| CLI default for a polling-aware run | 1,330 s | `H + T + 45` from submission, including request and observation margin. Individual HTTP requests use a short bound appropriate to the request. An explicit `--timeout` may end client observation earlier, with the ID available for resuming it. |

The ordering for the enabled end-to-end path is `CLI > T > W > S + C + K`. Budget setup from durable admission, including time before the worker transport opens. The enclosing activation can shorten the inference window. Carry its existing absolute deadline through the router and worker to launch. Recompute immediately after setup, reserve cleanup and response headroom, and use the smaller of `C`, remaining worker time and remaining activation time as the effective inference ceiling. Refuse before provider launch if the remaining budget cannot cover cleanup and a positive run. Derive monotonic launch deadlines from the computed durations and never restart the absolute clock in a fallback or repeated worker call. The existing activation budget and stop semantics retain authority.

Drain both backend output pipes continuously. Reset the monotonic inactivity clock on new output from the launched backend. A worker heartbeat, observation request or empty read cannot extend it. Close on the first of completion, inactivity or the effective absolute deadline. Preserve provider diagnostics, Codex model-response evidence and usage attribution. Verify each provider adapter's output behavior before opting it in, especially the GLM and Claude adapters that currently parse a terminal JSON object. They need a reviewed streaming-to-terminal adapter or an explicit pre-admission refusal in liveness mode. Prepared multi-call requests need a shared budget before qualification.

## Advisory ownership and recovery

Apply explicit ownership to newly admitted activation advisory rows at the legacy timeout as well. The switch controls inactivity timing and opt-in HTTP submission. A legacy synchronous request keeps its existing timeout and result shape. An ID admitted under the new mode must stay observable after the switch is turned off.

1. Reuse the existing `EstateExecution` ID and worker spool claim. Bind the ID to the initiating principal and request identity, or to the owning activation and card revision. Persist the claim before crossing the provider boundary. A same-ID query or submission can observe the existing claim. An altered payload, different owner or repeated start cannot launch it. Keep the current route authorization and apply the owner binding to advisory-only observation and result retrieval. Use the existing result surface with no lease or write finalization authority.
2. Give each advisory a dedicated runner on its attested worker host. Reuse the worker's durable claim and quiescence primitives. Record the host, process creation identity and dedicated cgroup before allowing provider launch. Use one runner lifetime for setup, execution and cleanup. The independent unit cleanup must cover the case where the control-plane process or advisory runner dies. A numeric PID, a transport exception and an expired timer provide insufficient evidence.
3. Keep launch ownership separate from result persistence. On normal completion, timeout, or exception, use the same idempotent conditional settlement after positive proof that the dedicated backend PID is gone and the unit contains no live descendants. Commit result, completion timestamp and terminal state together. If the terminal result was lost but the process is proven dead, record an interrupted execution with possibly unknown usage. Preserve the existing unknown-usage fence.
4. Reconciliation reads the same durable decision and worker status. If start acknowledgement is lost, the worker's existing claim-or-abort pattern must fence an unconfirmed launch before any interrupted settlement. If process identity or host status is uncertain, retain the same unresolved ID with an explicit reason. A later observation can settle it once positive evidence arrives. Older advisory rows retain the existing ID fence. Rows with only a shared PID and no child-life evidence remain unresolved until the current owner persists completion or safe quiescence can be established. Writer lifecycle and recovery are outside this change.

## Cross-family design review (2026-11-26)

Reviewer: claude-opus-5-5 (Claude family; the author is Codex, GPT family, so the review is independent). Verdict: **APPROVE_WITH_CONDITIONS**. The design may proceed to implementation (plan step 2 onward) only under these conditions, which are binding on the implementer and are repeated on the owner card:

1. Lost-acknowledgement recovery needs a CLIENT-generated idempotency key (UUIDv4) sent with the submit, stored unique on the execution row with a payload hash: same key and hash returns the existing row, same key with a different hash is 409, and a resubmission never charges `max_paid_calls` twice. Test it.
2. Polling is used only when the submit response explicitly says polling is supported; otherwise use the legacy bounds and never resubmit automatically (an older server or a rollback would otherwise spend twice). Roll back in this order: switch off, let in-flight ids reach a terminal state, then revert code. Schema changes are additive; test that the old reconciler leaves new-format rows alone.
3. N = 180 s is unproven for Codex: before opting Codex in, measure the longest silent gap between output events in real lab Codex runs, using the exact invocation through a pipe (not a pty), and set N above it with margin. Start with Codex only; GLM and Claude are refused before admission until a reviewed streaming adapter exists.
4. Cite the activation stall-detection threshold and add it to the ordering invariant: either it exceeds T, or it reads activity from the row. Do not repeat the conflict that got 365a6c76 reverted.
5. Stage it smaller for one lab host. Drop for stage 1: the dedicated runner, the cgroup, new principal binding. Instead run the provider in its own session (setsid); record host, boot_id, PID and /proc start time on the row; settle by conditional update in `finally` once the process group is empty; a restarted control plane's reconciler kills the orphaned group and records an interrupted run with unknown usage. A changed boot_id counts as proof the process is gone (otherwise unresolved rows hold occupancy forever and can deadlock the parallel-dispatch card). Existing route auth plus unguessable ids suffices. Add a cgroup only if a test shows descendants escaping the process group. Liveness mode is Linux lab only; the Windows home worker is refused before admission.
6. State what drives the run after submit returns (the control-plane thread holding the transport) and add a fault test that restarts the control plane mid-run, not only one that kills the runner.
7. Anchor the transport bound: the transport timeout is the remaining W measured from durable admission, plus 15 s. Keep the submit request short (30 s or less); H need not appear in the CLI formula.
8. Make the status claims evidence-backed: commit the bound-arithmetic script and its values or drop the claim; cite the file and function of the claim-or-abort and quiescence primitives or mark them unverified; record the author's actual model from Codex's `model:` line; reconcile the card showing `ready` while a lease and execution exist for it.
