## Long-horizon loop

1. choose the smallest highest-value dependency-ready unit;
2. execute under the applicable A1 -> A2 -> B -> C -> D and §5/§7/§12/§13/§15 rules;
3. verify by source evidence and governing clauses;
4. propagate only through the smallest affected scope;
5. reassess stopping/dependencies;
6. commit and push the coherent unit;
7. rerank the frontier;
8. continue immediately.

A clean commit/checkpoint is **not** a stop condition. Before any voluntary
return, explicitly prove that no safe dependency-ready work remains. If one
branch blocks, continue another.

Before classifying a paper as operator-gated/access-blocked, check reasonable
alternate lawful public-full-text routes (publisher OA, DOI/Crossref metadata,
Unpaywall/OpenAlex, public/institutional repositories and author copies where
appropriate). A publisher "open access" link can resolve to an abstract page or a
bot-walled host while a repository copy of the same work (author-affiliation
repositories listed under OpenAlex locations) or the journal's own open archive
reads freely: try those before recording an access ceiling. A Cloudflare/Anubis
challenge or publisher 403 is a stop for that host, never something to solve or
bypass. When the operator supplies a URL that met a bot-verification page, load it once
