## Focus 1 — round-12 fix, `registrable_domain` (`src/finance_mt_probe.py`)

**Holds.** I traced the guard at `src/finance_mt_probe.py:272-280` against a hostile battery by hand:

- **Empty labels are fully covered.** An empty label can only appear as a leading dot or two consecutive dots (a trailing dot is stripped in `_canonical_host` before the check, and the check runs *after* the second `_canonical_host` call, so percent-encoded forms `%2Ecom` / `a%2E%2Eb.com` decode *before* the `startswith(".")`/`".."` test). `".com"`, `"a..b"`, `".example.com"`, `"a...b"`, `"...com"`, `"com..net"`, `"..tr"`, `"./"`, `"...."` all → `"unknown"`.
- **Trailing dot still heals**: `https://example.com./p` → `example.com` (hostname's trailing dot stripped at `finance_mt_probe.py:229`, then normal two-label logic). Pinned by `test_registrable_domain_empty_label_forms`.
- **Single-label keeps the metadata fallback**: `https://com./x` → `"com"` (no dot) → `collect_gdelt` falls back to the `domain` metadata at `finance_mt_probe.py:452-453`.
- **IDN still canonicalises**: `faß.de` → `xn--fa-hia.de` via UTS-46; idna-absent and undecodable hosts return `""` → `"unknown"` (never an IDNA-2003 ß→ss split).
- **No legitimate form broken**: leading-dot and consecutive-dot hosts are invalid DNS, so nothing valid is newly rejected. IPv6 literals, brackets, port-only, `user:pass@` with no host, spaces, ill-typed input, `""` — all `"unknown"`.
- **Integration is right**: `"unknown"` contains no dot, so the metadata fallback runs; if metadata is also unusable the article is malformed *before* the exact-dedup check (`finance_mt_probe.py:454-470`), so repeats inflate `malformed`, never `deduped_exact` — exactly the pinned test.
